너는 부동산 데이터 분석 서비스를 여러 번 만들어 본 시니어 PM이자 아키텍트이고,
한국 부동산 시장(특히 경매·PF·금융·정책대출)에 밝은 애널리스트야.
이번 세션에서는 "기획"만 하고 코드는 작성하지 마. 개발은 다음 세션에서 따로 진행할 거야.

## 1. 만들려는 것
매일 대전 아파트 시장 데이터를 모아 리포트를 만들고, "지금이 내 매수 적기인지"를
점수와 근거로 판단해 주고, 추세를 그래프로 보여주는 개인용 앱.

## 2. 내 조건
- 직장: 대전 유성구 대덕연구단지. 출근 시간대 통근 30분 이내 지역 선호
  (자가용·대중교통 각각 기준으로 후보 생활권을 뽑아 줘)
- 유형: 아파트 매매, 실거주
- 평형: 84㎡ 우선, 59㎡는 신축(대략 준공 10년 이내)이면 검토
- 예산: 매매가 6억~10억 원 내외
- 자격: 무주택, 생애최초 주택 구입 해당
- 연소득: [ 예: 부부 합산 9천만 원 ] (DSR·대출 한도 계산용)
- 보유 자금: [ 예: 자기자본 3억 원 ]
- 마감: 현재 사택 거주 중이며 2030년 8월에 사택 기간 만료
  → 2030년 8월 전까지 잔금·입주가 끝나야 함
- 매수 경로: 일반 매매 / 경매 / 신축 청약·분양권 모두 고려
  (경매는 권리관계가 단순한 아파트 물건만)
- 사용 형태: 아이폰·안드로이드 모두 사용 (매일 아침 요약 알림 + 그래프 화면)
- 운영 비용: 완전 무료 (유료 API, 유료 서버, 앱스토어 개발자 계정 비용 없이)
- 개발 경험: [ 예: 파이썬 기초 가능 / 거의 없음, 코드는 Claude가 작성 ]

## 3. 판단의 핵심 질문
"매수할까 말까"가 아니라 아래 질문에 답하는 앱이어야 해.
1) 2030년 8월까지 남은 기간 안에서 지금 사는 게 나은가, 기다리는 게 나은가?
2) 매수 경로별 비교: 일반 매매 / 경매 낙찰 / 신축 청약·분양권 중 무엇이 유리한가?
   - 청약·분양권은 2030년 8월 전에 입주 가능한 단지만 대상
   - 경매는 낙찰 → 잔금 → 명도까지 걸리는 기간을 반영
3) 기다린다면 "이 신호가 나오면 사라"는 트리거가 무엇인가?
4) 마감이 다가올수록 타이밍보다 '확실한 입주'가 중요해지므로,
   남은 기간(D-day)에 따라 판단 기준이 바뀌는 구조로 설계해 줘.
   각 경로별로 "늦어도 이때는 행동을 시작해야 한다"는 역산 일정도 만들어 줘.

## 4. 내 자격 조건 반영 (웹 검색으로 현재 기준 확인 필수)
- 생애최초 혜택: LTV 우대, 취득세 감면, 생애최초 특별공급 자격(소득·자산 기준)
- 정책대출: 디딤돌대출, 보금자리론 등 주택가격·소득 한도를 확인하고
  예산 6~10억 구간에서 어떤 가격대부터 대상에서 빠지는지 표로 정리
- 시중은행 주담대: 스트레스 DSR 포함 내 소득 기준 대출 가능액 계산식
- 대전의 규제지역 여부, 토지거래허가구역 여부
- 경매 시 경락잔금대출 가능 여부와 한도
- 위 결과를 "가격대별 필요 자기자본과 월 상환액" 표로 만들어 앱에 넣을 것

## 5. 후보 지역·단지 필터
- 대덕연구단지 기준 통근 30분 이내 생활권 후보를 뽑고
  (예: 유성구 도룡·어은·전민·노은·도안·관평, 서구 둔산·월평·만년 등. 실제 소요시간으로 검증)
- 조건: 84㎡ 우선 / 59㎡는 신축만, 매매가 6~10억
- 단지별 점수: 통근 시간, 연식, 세대수, 학군, 최근 실거래 추세, 매물 수
- 통근 시간 계산에 쓸 수 있는 무료 API(카카오·네이버·TMAP 등) 한도를 확인하고,
  어려우면 단지별로 한 번만 계산해 고정값으로 저장하는 방식 제안

## 6. 반드시 반영할 지표와 용어 (현장 실무자 글에서 가져온 개념)
아래 개념을 지표로 만들 수 있는지, 대전 단위 데이터가 있는지 조사하고 SCORING에 반영해 줘.
글쓴이의 주장 자체는 검증되지 않았으므로, 데이터로 확인 가능한 것만 쓸 것.

[경매 지표: 선행 지표 + 실제 매수 기회 탐색]
- 대전 아파트 경매 신청·진행 건수 추이
- 유찰 횟수, 감정가 대비 최저가·낙찰가율 (1회 유찰 시 보통 감정가의 70~80%)
- 임의경매 비중 (담보대출을 못 갚아 금융기관이 신청한 경매)
- 임의취소(무잉여 기각): 경매로 팔아도 선순위 채권자 몫을 빼면 남는 게 없어 취소된 건
- 낙찰 후 잔금 미납 → 재매각 건수 (낙찰자가 보증금을 포기할 만큼 매수 여력이 약하다는 신호)
- 내 조건에 맞는 경매 물건 알림. "권리관계 단순" 판정 기준을 정의해 줘
  (예: 말소기준권리 이후 인수할 권리 없음, 대항력 있는 임차인 없음,
   유치권·법정지상권·지분경매 아님, 명도 난이도 낮음)
  자동 판정이 어려운 항목은 "직접 확인 필요"로 표시

[금융 지표]
- 주택담보대출 금리, 기준금리, 은행·제2금융권 연체율
- "연체율 착시" 가능성: 단기 대환대출, 이자 유예, 경매 신청 지연 때문에 연체율이
  실제보다 낮게 보일 수 있음 → 연체율과 경매 신청 건수를 함께 봐서 괴리를 지표화
- NPL(부실채권) 매각 할인율: 할인율이 클수록 담보 가치에 대한 시장 평가가 낮다는 뜻

[PF·공급 지표]
- 대전 PF 사업장 현황: 브릿지론에서 본PF로 넘어가지 못하고 만기 연장 중인 사업장
  (브릿지론: 인허가 전 토지 매입용 고금리 단기 대출, 본PF: 착공 후 시공사 보증·분양 대금 담보 대출)
- 공사비 상승으로 인한 시공사 책임준공 리스크 → 청약 단지가 2030년 8월 전에 실제 입주 가능한지
- 대전 입주 예정 물량, 미분양·준공 후 미분양 추이

[수요·심리 지표]
- 실거래 건수와 가격 추이, 매물 증감, 전세가율
- "유동성 증발" 여부: 가격 하락보다 거래 자체가 사라지는지 (거래량, 경매 낙찰률)
- 상가 공실률·렌트프리(일정 기간 임대료 면제) 확산은 참고 지표로만 사용

## 7. 기획에 꼭 들어가야 할 것
1) 서비스 개요: 목표, 하루 사용 흐름, MVP 기능 / 제외 기능
2) 데이터 소스 조사: 4~6번 항목별로 실제 사용 가능한 무료 소스를 표로 정리
   - 후보: 국토부 실거래가 API(공공데이터포털), 한국부동산원 R-ONE, 한국은행 ECOS,
     금융감독원 금융통계정보시스템, 국토부 통계누리(미분양), 청약홈, 대한민국 법원경매정보,
     통계청 KOSIS, 주택도시기금(정책대출), 부동산 뉴스 RSS
   - 소스마다 제공 지표, 대전 단위 제공 여부, 갱신 주기(일/월/분기), API 키 필요 여부,
     이용약관상 크롤링 허용 여부(특히 법원경매정보)를 정리하고, 불가능하면 대체 방법 제시
   - 웹 검색으로 현재 제공 여부를 반드시 확인
3) 진입 판단 점수 로직
   - 지표별 가중치와 산식, 0~100점 구간(예: 적극 매수 / 분할 검토 / 관망 / 보류)
   - D-day에 따라 가중치가 바뀌는 방식
   - 경로별 점수(일반 매매·경매·청약) 따로 산출
   - 오늘 날짜 기준 예시 계산 1개
   - 한계와 "투자 자문이 아님" 고지
4) 그래프 목록: 어떤 차트를 어떤 데이터로 그릴지
   (예: 후보 생활권별 84㎡ 매매가 추이, 거래량, 경매 건수 vs 연체율 괴리, 낙찰가율,
    금리 vs 가격 이중축, 입주 물량, 점수 히스토리, 2030년 8월까지 경로별 타임라인,
    가격대별 필요 자기자본·월 상환액)
5) 데일리 리포트: 항목, 분량(휴대폰 한 화면), 발송 시간, 예시 리포트 1개
6) 아키텍처 (완전 무료 조건)
   - 아이폰·안드로이드 둘 다 쓸 수 있는 방식 비교: PWA(홈 화면 추가) / 텔레그램 봇 /
     Expo 네이티브 앱 / 웹 대시보드. 앱스토어 비용 없이 가능한 조합 추천
   - 수집 스케줄링(예: GitHub Actions cron), 저장소(예: SQLite, Supabase 무료),
     호스팅(예: GitHub Pages, Streamlit Cloud, Vercel 무료)의 무료 한도 확인
   - 구조도, DB 스키마 초안, 대안 1개와의 비교
7) LLM 활용: 무료 조건에서 뉴스 요약이나 리포트 문장에 쓸 수 있는지, 없으면 템플릿 방식
8) 리스크: 데이터 지연, API 한도, 크롤링 법적 이슈, 판단 로직 오류, 무료 서비스 정책 변경,
   정책대출 기준 변경
9) 개발 로드맵: 2세션에서 진행할 마일스톤별 체크리스트와 완료 기준

## 8. 진행 방식
- 시작 전에 애매한 부분이 있으면 먼저 질문해 줘(최대 5개).
- 결정 지점마다 선택지 2~3개와 추천안을 제시해 줘.
- 용어는 처음 나올 때 한 줄로 풀어서 설명해 줘.
